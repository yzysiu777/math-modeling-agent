# 通用任务路由矩阵

## 1. 路由输出

路由器只能输出以下之一：

- `optimization`
- `data_analysis`
- `hybrid`
- `insufficient_information`

路由是建议，不是不可撤销决定。`human_owner` 可以覆盖，但必须记录理由和影响。

## 2. 输入信号

| 信号 | Optimization 分 | Data Analysis 分 | 说明 |
|---|---:|---:|---|
| 存在可控决策变量 | 2 | 0 | 分配、选择、顺序、路径、产量、库存等 |
| 存在硬约束和可行域 | 2 | 0 | 容量、预算、时间、资源、逻辑、守恒 |
| 目标是最小化/最大化 | 2 | 0 | 成本、收益、风险、时间、服务水平 |
| 需要最优性、界或可行性证明 | 2 | 0 | 需要求解器、界或独立约束检查 |
| 核心输入是观测样本 | 0 | 2 | 行为、测量、历史记录、传感器或调查数据 |
| 目标是描述、解释、推断或预测 | 0 | 2 | 回归、分类、聚类、趋势、异常 |
| 存在标签、时间切分或交叉验证 | 0 | 2 | 需要泄漏和泛化审查 |
| 需要统计不确定性 | 0 | 2 | 区间、检验、校准、预测区间 |
| 预测结果进入后续决策 | 2 | 2 | 典型 Hybrid |
| 决策反馈改变后续数据 | 2 | 2 | 需因果、在线或闭环边界 |

建议阈值：某轨道得分不低于 4 且比另一轨道高至少 2，选择该轨道；两轨道都不低于 4，选择 `hybrid`；关键信息缺失时选择 `insufficient_information`。阈值必须通过合成评测校准，不能视为永恒规则。

## 3. 路由记录必填字段

```yaml
schema_version: "2.0"
routing_id: "ROUTE-YYYYMMDD-0001"
problem_contract_hash: ""
route: "optimization | data_analysis | hybrid | insufficient_information"
confidence: 0.0
signals: []
required_tracks: []
unresolved_questions: []
assumptions_used: []
recommended_artifacts: []
router: ""
reviewer: ""
human_override:
  applied: false
  owner: ""
  reason: ""
created_at: ""
```

路由器不得根据“用了机器学习名称”或“出现最优二字”单点判断。必须回到任务目标、可控变量、观测数据、约束和评价方式。

## 4. Optimization 二级路由

| 结构 | 首选 baseline | 候选方法 | 必查证据 |
|---|---|---|---|
| 连续线性 | LP | 分解、灵敏度 | 可行性、对偶/界、容差 |
| 0-1/整数逻辑 | 简化 MILP/枚举 | MILP、CP-SAT、分支定界 | gap、证书、规模 |
| 网络结构 | 小图枚举 | 最短路、流、匹配 | 状态、边、守恒、最优对照 |
| 排程/资源 | 贪心/list baseline | MILP、CP、局部搜索 | 资源、先后、冲突、完工时间 |
| 路径/选址 | 简化构造解 | VRP、设施选址、分解、启发式 | 每条硬约束、下界、可行性 |
| 库存/动态决策 | 静态或单期 baseline | DP、滚动优化、随机规划 | 状态转移、边界、情景 |
| 不确定优化 | 名义情景 | 随机/鲁棒/分布鲁棒 | 分布/集合依据、风险度量 |
| 多目标 | 单目标极点 | 权重、词典序、ε-constraint | Pareto、权重敏感性 |
| 非线性/非凸 | 松弛或局部 baseline | NLP、全局法、启发式 | 初值、局部性、界、容差 |

## 5. Data Analysis 二级路由

| 目标 | 首选 baseline | 候选方法 | 必查证据 |
|---|---|---|---|
| 描述与探索 | 分布/交叉表 | 稳健统计、可视化 | 粒度、缺失、样本偏差 |
| 回归预测 | 均值/线性模型 | 正则、树、集成、非线性 | 切分、误差、区间、残差 |
| 分类预测 | 多数类/Logistic | 树、集成、核方法等 | 类不平衡、校准、阈值 |
| 时间预测 | naive/seasonal naive | ARIMA、状态空间、ML | 滚动回测、未来泄漏、漂移 |
| 聚类 | 简单距离基线 | k-means、层次、密度 | 缩放、稳定性、可解释性 |
| 降维 | PCA | 非线性嵌入 | 方差、稳定性、下游价值 |
| 异常检测 | 规则/分位数 | 孤立、密度、预测残差 | 标签缺失、误报、阈值 |
| 统计推断 | 描述统计 | 检验、区间、回归调整 | 假设、效应量、多重比较 |
| 因果问题 | 明确“仅关联” baseline | 仅在识别假设充分时进入因果方法 | 识别、混杂、重叠、敏感性 |

## 6. Hybrid 接口

Hybrid 必须拆成至少三个工件：

1. `data_analysis_output`：估计值、模型版本、不确定性和适用范围；
2. `hybrid_interface_contract`：字段、单位、情景生成、缺失值和版本；
3. `optimization_input_manifest`：实际被优化器消费的数据及哈希。

联合验收指标至少包括：预测/估计质量、决策目标、硬约束可行性、情景稳健性和相对 baseline 的决策增益。

## 7. 路由纠错

- G1 前允许自由修订路由；
- G1 后改变主路由，必须使下游合同、baseline、实验和论文 claim 失效；
- 轻微增加辅助轨道可以保留已验证工件，但必须记录接口版本；
- 若题意不足，路由器必须停在 `insufficient_information`，不能用常识补造变量、标签或约束。
