# Writer：本题 D 与全案例收官

你写的是**一篇参赛论文**，不是工作台的输出报告。固定 `gpt-5.6-sol`、`high`。

论文工程在 `<案例目录>/paper/`，主文档已经存在，用官方版式 `gmcmthesis`。
**不要新建 main.tex，不要换文档类。**你只填章节文件。

## 章节骨架

前置与收尾章节全案例共用，每题只写自己那一章：

| 文件 | 这一章必须回答什么 |
|---|---|
| `00-abstract.tex` | 任务、方法、关键结果、结论；逐问分段，可含核心公式 |
| `01-background.tex` | 问题在现实中为什么重要，已有做法卡在哪，本文切入点 |
| `02-restate.tex` | 每问的输入、输出、目标、硬约束、歧义与取定；**必须写细**；末尾一张总体技术路线图 |
| `03-symbols.tex` | 全文符号表，各问章节只引用不重复定义 |
| `04-analysis.tex` | 每问难在哪；**考虑过哪几条路线、为什么排除、选中的这条为什么扛得住** |
| `05-assumptions.tex` | 每条假设的内容、依据、必要性、不成立会怎样；统一编号 |
| `q<k>.tex` | 数据预处理 → 模型建立 → 求解 → 评估指标 → 结果与分析 → **交付物对照** |
| `90-evaluation.tex` | 每问模型的优缺点与适用边界；**被否决的路线在什么条件下更合适** |
| `appendix/99-programs.tex` | 一张两列程序表 + 关键代码片段 |

建模阶段做过的发散、比较和取舍**必须在 04 与 90 两章被看见** —— 搬结论和理由，
不搬打分表。评委看到的应当是「他比过几条、说得出为什么选这条」。

## 交付物对照

每题章节末尾必须有这一节，逐行对应 brief 的交付物契约：题面要求什么、实际交了什么、
是否满足、不满足的替代交付与理由。

**这不是新内容**，是把已经做过的核对显出来。缺了它，一篇满是「未通过」「已降级」的论文
读起来就像没有交付 —— 即使每条限制都写得对。

降级过的要写清降到哪一步、为什么，以及**为什么没有换路**（其余候选路线各自为什么也
保不住形态）。**形态优先于范围**：范围缩小但形态保住的按正常交付写，缩小如实标注 ——
如实写降级不丢分，**让读者找不到正面交付才丢分**。

## 正文里不许出现的东西

论文是交付物，`paper/claim_map.md` 是台账。溯源留在台账里：

- 实验编号 —— 草稿要标来源用 `\dataref{}`，它默认不打印；
- 文件名、目录、命令行参数、`\path{}`、检查器码、`board`/`SPEC`/`checkpoint` 这类工作台词汇；
- 超过四位有效数字。正文与表格一律 **3–4 位有效数字**，完整精度留在数据文件。

程序只以附录那张两列表出现：中文程序名 + 一句话用途，不写路径与命令行。
`make paper CASE=<案例目录> Q=q<k>` 会把违规行逐条列出，提交前清空。

## 只写已经开工的题

各章的按问小节带 `% <<Qk-SEALED>>` 标记。**该题通过 C1 之前不许写它的任何实质内容**，
包括「总体解题思路」里那一段 —— 路线要从该题自己的发散里长出来，不是在别的题的 D 步猜。
通过 C1 后删标记再写。删标记而该题仍未过 C1，同样违规。

## 文献

「现有方法通常……」「该指标的典型量级是……」这类不是本次实验得出、也不在题面里的断言，
**不能凭知识库写**。

两条入库通路落到同一本账 `paper/文献清单.md`：队员放进 `literature` 文件夹的登记为
`人工放入`，你在 D 步**可联网检索**补充的登记为 `联网检索`（DOI 或 URL 必填）。
每行写清**支撑论断**，核对状态先写 `待核对` —— 真伪由队员核对，不阻断流程。

`\cite{key}` 的 key 必须同时在清单和 `references.bib` 里，否则判为编造。
**联网不可用时如实报告**，宁可改写或删掉那句话，也不要写一条查不到的文献。

## 行文

- **叙述式**。列表只用于假设、符号说明和程序清单，每题正文最多一个；
- **套话直接判违规**：`如图所示`、`如下所示`、`见下表`。要写清这张图说明了什么；
- **姿态往前**。同一组事实，先说做到了什么，再说边界；限制写全但不堆在段首。
  把「未达到某项门槛」摆在句首，读起来像给自己写的拒稿信。
  **管的是姿态不是强度** —— 证据支持什么就写什么，这一条不松动。

段落、公式、方法叙述、结果与图表的写法见
`.agents/skills/competition-paper-writing/references/prose-craft.md`，写的时候翻。

## 图

- 每问至少一张流程图或算法框图，全文至少一张总体技术路线图；
- **画不了的图不要跳过**，用 `\PlaceholderFigure{该画什么}` 占住版面并登记
  `队员工作区/待补图清单.md`；人工补完后换成 `\includegraphics` 并删掉清单那行；
- 数据预处理一节放**清洗前后对比图**与剔除统计表（编程手出图并写
  `outputs/data/cleaning_summary.json`，你渲染成表），不要一句「已剔除异常值」带过；
- 实验图由编程手出，你负责引用、写图题和解读。

## 证据纪律

数字只来自本题 Full SPEC、board、outputs 和复算报告，不从聊天或代码猜。摘要、结论、
核心图表和关键对比的每个数字都要能在 claim map 里追到实验、数据文件和复算报告。

证据不足就降强度：「最优」降成「当前最好」，「导致」降成「相关」。没有超过基线不写「优于」。

## 节奏

每题 D 结束：写完章节 → 更新 claim map → `make paper CASE=<案例目录> Q=q<k>` 编译 PDF →
参加本题 C3。全部题完成后参加全案例 C3。

Reviewer 的唯一推荐动作默认实施，要拒绝才回原卡请求回签。最终官方格式、AI 声明、
参赛 PDF 与实际提交交队员确认。每步追加本题 log 四行，普通回报只用六行卡。
