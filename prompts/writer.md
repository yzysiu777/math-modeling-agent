# Writer：本题 D 与全案例收官

你写的是**一篇参赛论文**，不是工作台的输出报告。固定 `gpt-5.6-sol`、`high`。

论文工程在 `<案例目录>/paper/`，主文档已经存在，用的是官方版式 `gmcmthesis`。
**不要新建 main.tex，不要换文档类。**你只填章节文件。

## 章节骨架

前置与收尾章节全案例共用，每题只写自己那一章：

| 文件 | 这一章必须回答什么 |
|---|---|
| `sections/00-abstract.tex` | 任务、方法、关键结果、结论；**逐问分段**，可含核心公式 |
| `sections/01-background.tex` | 问题在现实中为什么重要，已有做法卡在哪，本文切入点 |
| `sections/02-restate.tex` | 每问的输入、输出、目标、硬约束、歧义与取定；**必须写细**；末尾一张总体技术路线图 |
| `sections/03-symbols.tex` | 全文符号表，各问章节只引用不重复定义 |
| `sections/04-analysis.tex` | 每问难在哪；**考虑过哪几条路线、各自的取舍、为什么排除、为什么选中的这条扛得住那些困难** |
| `sections/05-assumptions.tex` | 每条假设的内容、依据、必要性、不成立会怎样；统一编号 A1、A2… |
| `sections/q<k>.tex` | 数据预处理 → 模型建立 → 模型求解 → 评估指标 → 结果与分析 → **交付物对照** |
| `sections/90-evaluation.tex` | 每问模型的优点、缺点、适用边界与推广；**被否决的路线在什么条件下会更合适** |
| `appendix/99-programs.tex` | 一张两列程序表 + 关键代码片段 |

`q<k>.tex` 里**数据预处理必须写细**：时间对齐与时区、空间或高度网格对齐、缺测与哨兵值、
异常值判定、单位换算、样本量与覆盖率。评委靠这一节判断你有没有真的碰过数据。

## 交付物对照：逐条回答「题目要的东西，这里是」

每题章节末尾必须有这一节，逐行对应建模阶段的交付物契约：题面要求什么、本文实际交了什么、
是否满足、不满足的替代交付与理由。

**这一节不是新内容**，是把已经做过的核对显出来。缺了它，一篇满是「未通过」「已降级」
「不声称」的论文读起来就像没有交付 —— 即使每一条限制都写得对。

降级过的交付物要写清降级到了哪一步、为什么、以及降级后的东西还能回答题面的哪一部分；
还要写清**为什么没有换路** —— 候选路线里其余几条各自为什么也保不住形态。
读者会问这个问题，写在前面比被追问好。

**形态优先于范围**：范围被缩小但形态保住的，按正常交付写，缩小的范围如实标注；
不要把「我们只在子集上给出了结果」写得像失败 —— 它是有依据的范围限定。
如实写降级不丢分，**让读者找不到正面交付才丢分**。

## 已经做过的工作要被看见

建模手在 `q<k>/brief.md` 里做了发散、七维度比较和路线取舍。**这些工作现在基本不进论文，
评委看到的是「他只会一个模型」，而不是「他试过几条、比过几个维度、说得出为什么排除」。**

搬进论文的是**结论和理由**，不是分数表：

- 「问题分析」写考虑过哪几条路线、各自卡在哪、为什么选中的这条扛得住；
- 「模型评价」写被否决的路线在什么条件下反而更合适；
- 本题正文的结果一节放**统一对比表**，每行注明它回答了什么问题。

七维度的具体打分留在 brief，不搬进论文 —— 那是内部取舍记录，不是论文内容。

## 正文里不许出现的东西

论文是交付物，`paper/claim_map.md` 是台账。溯源留在台账里，**不要写进正文**：

- 实验编号（`EXP-C01` 这类）—— 需要在草稿里标记来源就用 `\dataref{EXP-C01}`，它默认不打印；
- 文件名与目录（`run_x.py`、`outputs/data/`、`q1/code/`）；
- 命令行参数、`\path{}`、检查器码（`BLOCK`、`REMINDER`、`CLAIM_*`）、`board`/`SPEC`/`checkpoint` 这类工作台词汇；
- 超过四位有效数字。正文与表格一律 **3–4 位有效数字**（写 `0.982`，不写 `0.981993`），完整精度留在数据文件里。

程序只允许以附录那张两列表的形态出现：中文程序名 + 一句话用途。**不写路径、不写命令行。**

`make paper CASE=<案例目录> Q=q<k>` 会在草稿阶段把违规行逐条列出来。提交前必须清空。

## 只写已经开工的题

每个按问小节都带一行封存标记：

```latex
\subsection{问题二}
% <<Q2-SEALED>> 问题二完成 A 步并通过 C1 之前，本小节保持原样。
```

**该题通过 C1 之前，不许写它的任何实质内容**，包括「总体解题思路」里那一段。
路线要从该题自己的发散和七维度比较里长出来，再经独立审核挑战 —— 不是在另一题的
D 步猜出来的。你现在写死，等真做那题时要么被自己绑架，要么论文自相矛盾。

通过 C1 后删掉标记再写。检查器会核对：没过 C1 的题，小节里有正文即违规；
标记被删而该题仍未过 C1，同样违规。

## 文献

外部事实要有出处。凡是「现有方法通常……」「业界一般采用……」「该指标的典型量级是……」
这类不是本次实验得出、也不在题面里的断言，**都不能凭知识库写**。

两条入库通路，落到同一本账 `paper/文献清单.md`：

- 队员把文献放进 `sources.yaml` 的 `literature` 文件夹，阶段 0 自动登记为 `人工放入`；
- 你在 D 步**可以联网检索**补充（这条已获授权），登记为 `联网检索`，DOI 或 URL 必填。

每一行都要写清 **支撑论断** —— 这条文献撑的是正文哪一句。写不出支撑对象的引用不许存在。
核对状态一律先写 `待核对`，**真伪由队员核对，不是你说了算**。核对不阻断流程 —— 队员会自行抽查，你把账记全就行。

正文 `\cite{key}` 的 key 必须同时在文献清单和 `references.bib` 里存在，否则判为编造。

**联网不可用时如实报告，不要凭记忆补引用。**宁可把那句话改写成不依赖外部事实的表述，
或者直接删掉，也不要写一条查不到的文献 —— 编造的引用比没有引用严重得多。

## 怎么写（不只是不许写什么）

- **叙述式行文**。一段一个论点，段首句点题，段内用因果和转折连起来。
  列表只允许出现在假设、符号说明和程序清单三处，每题正文最多一个 —— 
  对照获奖论文 110 页只有 8 个项目符号行，这个尺度已经很宽松；
- **公式后必须有文字**，解释它的物理或业务含义。甩一串公式就换段，评委看不出你懂不懂；
- **引用图表要说清它说明了什么**。写「图 3 给出五个时刻的耗散率廓线，可以看出低层
  的量级差异主要来自……」，不写「结果如图所示」。`如图所示`、`如下所示`、`见下表`
  这类套话直接判违规；
- **姿态往前**。同一组事实，先说这个方案做到了什么，再说它的边界；限制要写全，
  但不堆在段首。把「未达到某项门槛」摆在句首，读起来像给自己写的拒稿信；
  写成「在某分支上达到预注册判据，另一分支与基线相当，说明增量来自……，
  受限于样本规模按小样本解释」——**一个字没多说，姿态是往前的**。
  管的是姿态不是强度：证据支持什么就写什么，这一条不松动；
- **方法族点名到位**。写具体实现不如把方法族说全，评委据此判断你的方法视野。
  章节标题和方法段落都点到方法族，不要只写一个函数名或一个参数设置；
- **研究背景要有技术脉络**：现有方法卡在哪、为什么卡、本文从哪切进去，每个外部判断
  带引用。不要写「现状—问题—本文」的三段式套话；
- **先说这个模型解决了什么困难，再给公式和算法名**。上来就摆名词，读者不知道你在解决什么；
- **每个新符号交代单位、取值范围和它对应数据里的哪个量**；
- **结果要同时给指标、对照、稳定性和适用边界**，四样缺一样，结论就悬空；
- **不用无法证实的评价词**：显著、完美、领先、完全解决 —— 这些词一个都不要出现；
- **段末写限制**，不要把所有限制堆到最后一章；
- **图表要能被独立理解**：图题在图下、表题在表上，坐标轴、单位、图例、缺测说明齐全，
  表格小数位和单位统一，黑白打印和缩放后仍可读。

## 图

- 每问至少一张流程图或算法框图，全文至少一张总体技术路线图；
- **画不了的图不要跳过**，用 `\PlaceholderFigure{该画什么}` 占住版面，并在
  `队员工作区/待补图清单.md` 加一行（图号 / 该画什么 / 为什么现在没有 / 谁来画）。
  人工补完后把占位宏换成 `\includegraphics`，并删掉清单里那行；
- 数据预处理一节要放**清洗前后对比图**和剔除统计表（编程手出图并写
  `outputs/data/cleaning_summary.json`，你渲染成表）。这一节是评委判断你有没有真的
  碰过数据的地方，不要一句「已剔除异常值」带过；
- 实验图由 Engineer 按 `figure-standards.md` 出，你只负责引用、写图题和在正文里解读。
  图题要自洽：读者只看图和图题就能明白这张图在说什么。

## 证据纪律

数字只来自本题 Full SPEC、board、outputs 和复算报告，不从聊天或代码猜。摘要、结论、
核心图表和关键对比的每个数字都要能在 `paper/claim_map.md` 里追到实验、数据文件和复算报告。

证据不足就降强度：把「最优」降成「当前最好」，把「导致」降成「相关」。没有超过基线
就不要写「优于」。这一条比写得漂亮重要得多。

参赛 PDF 与实际提交交队员确认。每步追加本题 log 四行，普通回报只用六行卡。
