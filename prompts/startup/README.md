# 启动提示词模板

`prompts/` 下的 `modeler.md`、`engineer.md`、`writer.md`、`orchestrator.md`、
`reviewer/` 是**角色协议** —— 长、详细，由 agent 自己去读。

本目录是**启动提示词模板** —— 短、可直接复制，由人填空后粘进新会话，把 agent
拉到那个角色上。两者分工：协议是内容的唯一真源，模板只负责把 agent 指过去，
再补上「这一轮的边界」。

**模板里不复述协议内容。** 复述就会有两份规则，改一处忘一处。

## 目录

| 模板 | 启动谁 | 门控条件 |
|---|---|---|
| [orchestrator.md](orchestrator.md) | 调度者 | 开局；或需要一个 agent 做人机接口时 |
| [modeler.md](modeler.md) | 建模手 | 案例已建、`input/` 已备齐 |
| [engineer.md](engineer.md) | 编程手 | 某份规格 `make spec-check` 通过；C1 建议已由人处理 |
| [writer.md](writer.md) | 写作手 | 已有稳定且复算通过的实验结果 |
| [reviewer.md](reviewer.md) | 对抗审核 C1/C2/C3 | 见模板内的三个节点时机 |

## 怎么用

1. 打开对应模板，照「填空清单」把 `<...>` 全部替换掉；
2. 复制「提示词正文」整块；
3. **开一个全新会话**，粘贴，发送；
4. agent 按协议工作，到达模板写明的停止点后回报。

**每个角色一个独立会话。** 同一会话里切角色，下游会带着上游的推理走，
隔离就没了 —— 那是这套设计唯一在防的东西。

## 两个必填、最容易漏的槽

**`<本轮边界>`** —— 这一轮做到哪一步、到哪停、停下时报告什么。

不填的后果实测中出现过：建模手一路做到 probe，把还没核定的输出网格当成前提，
判据由调度者临时补设 —— 整条路线的证据链就废了。**分阶段启动比一次性放开安全得多。**

**`<硬范围>`** —— 明确不做什么。竞赛题目通常远大于一轮能做完的量，
不写死范围，agent 会自己扩。

## 填空规范

- 路径一律写**绝对路径**。实测中出现过相对路径在切换目录后失效。
- 案例目录、项目根目录分开写清楚，两者不在同一处。
- 数据只读的话就写明「只读，不复制不软链」。

## 与案例级交接文档的关系

具体某道题的范围、数据陷阱、命令清单，写在那道题自己的交接文档里
（例如实战目录下的「流程与注意事项」），**不要写进这里的模板** ——
模板是跨题目复用的。填空时从那份文档里取值。
