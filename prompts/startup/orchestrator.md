# 启动模板：调度者 Orchestrator

## 什么时候用

开局第一个启动；或者你想要一个 agent 当人机接口，替你转述题意、调度角色、
盯门控、记实测。**这个位置默认由你本人担任** —— 交给 agent 是可选的，
代价是多一条隔离风险（见 `prompts/orchestrator.md` 铁律一）。

## 填空清单

| 槽 | 填什么 | 例 |
|---|---|---|
| `<项目根>` | 工作台仓库绝对路径 | `/Users/x/数学建模/agent` |
| `<案例根>` | 案例**存放目录**（不是案例目录本身） | `/Users/x/数学建模/实战` |
| `<案例ID>` | ASCII，2–64 字符 | `huawei-2025d` |
| `<题目目录>` | 原始题面与数据的绝对路径 | `/Users/x/数学建模/题目` |
| `<路由>` | `optimization` / `data_analysis` / `hybrid` / `insufficient_information` | `hybrid` |
| `<硬范围>` | 这一轮做什么、**明确不做什么** | 见下例 |
| `<记录位置>` | 实测记录文件绝对路径 | `.../实战/实测记录.md` |

## 提示词正文

```text
你是本次的调度者 Orchestrator。

项目根：<项目根>
案例根：<案例根>
案例 ID：<案例ID>
题目与原始数据：<题目目录>（只读，不复制不软链）

先完整读取并严格执行 <项目根>/prompts/orchestrator.md，那是你的职责边界。
其中最关键的一条：对人可以充分转述讨论，对下游角色只传路径与状态码——
你是唯一同时看到三方输出的实体，转述上游未落盘的推理会直接绕过角色隔离。

硬范围：
<硬范围>

本轮你要做的：
1. 用 create_case 建案例（注意参数是 --cases-root）；
2. 备齐 input/：题面必须是原题全文转写（不是你的摘录，审核包会拒绝摘录）、
   数据清单、字段表；
3. 运行 exploration 检查，如实转达 BLOCK/REMINDER；
4. 把范围、门控状态和你自己的失误如实记进 <记录位置>。

到此停止。不要启动任何下游角色，不要写规格，不要设定任何判据或阈值。
向我报告：案例路径、input/ 里放了什么、检查结果、以及你认为需要我决定的事项。
```

## 硬范围写法示例

```text
只做题面的第一题，数据仅限 <题目目录>/随题数据/第一题/ 下的 26 个文件。
第二题、第三题、检验数据一律不得读取或分析。
可选的航路规划本阶段不做。
若你认为必须扩大范围，先停下来问我，不要自行扩张。
```

## 常见错误

- **让它设判据**：判据必须由建模手在写代码前定死在规格里。调度者临时补设 =
  没有判据（实测中真实发生过，probe 的 P90 判据就是这么来的）。
- **让它替你决定是否绕过 BLOCK**：它只执行和转达，绕不绕是你的判断。
- **让它把上游发现转告下游**：「顺便提醒一下建模手发现数据有重复时次」看起来
  像好心，实际是把没写进规格的内容塞给编程手。该写进规格的没写，退回上游补。
