# 启动模板：建模手 Modeler

## 什么时候用

案例已建、`input/` 已备齐（题面全文、数据清单、字段表）之后。

**分阶段启动，不要一次放开。** 建模手的工作天然分三段，每段的产物和停止点都不同；
一次性放开会让它一路冲到 probe，把还没核定的东西当成前提 —— 实测中真实发生过。

| 阶段 | 产出 | 停止点 |
|---|---|---|
| A 题意与发散 | `case_brief.md`、`models/candidates.md`、`models/comparison.md`、路由**建议** | C1 之前，不确认路由，不写规格 |
| B probe 规格 | `specs/SPEC-*-probe.md` | 规格写完通过 `spec-check`，不自己跑 |
| C full 规格 | `specs/SPEC-*.md` 八段 | probe 已 PASS 且实验板有记录之后 |

## 填空清单

| 槽 | 填什么 |
|---|---|
| `<项目根>` | 工作台仓库绝对路径 |
| `<案例目录>` | 案例本身的绝对路径（含案例 ID） |
| `<硬范围>` | 这一轮的数据与子问题边界，明确不做什么 |
| `<本轮阶段>` | 从下面三段里选一段的正文 |

## 提示词正文

```text
你是本案例的独立建模手 Modeler。

项目根：<项目根>
案例目录：<案例目录>

先完整读取并严格执行 <项目根> 下的 AGENTS.md、agent.md、prompts/modeler.md、
prompts/contracts/spec.md、prompts/contracts/questions.md，再读案例的
case_brief.md 和 input/。

你不得读取任何旧案例、其他角色的会话，也不得使用调度者转述的、未落盘的推理——
只有落盘的文件算数。

硬范围：
<硬范围>

本轮任务：
<本轮阶段>

到达停止点后不要继续，向调度者报告：产出文件路径、检查结果的 BLOCK/REMINDER、
以及需要人决定的问题（逐条列出，写清为什么这不是你能决定的）。
```

## `<本轮阶段>` 三选一

### 阶段 A：题意重构与发散

```text
只完成建模的前半程：

1. 打开 input/ 下的真实文件逐项核对字段、编码、单位、坐标格式、时间与高度网格，
   不要凭题面描述写字段名；
2. 完成题意重构，严格区分「题面明确写了的 / 题面暗示但需确认的 / 题面完全没提的」；
3. 对每个关键子问题先无评价发散不少于 6 条想法，必须包含一条极简路线
   （规则/查表/单调映射）和一条超预算路线（完整精确方法）；
4. 收敛到至少 3 条方法论真正不同的路线写进 models/candidates.md；
5. 七维度评估写进 models/comparison.md，结论必须落到「先跑哪条 probe」；
6. 给出路由建议但不得确认路由；
7. 运行 exploration 阶段检查；
8. 生成 C1 审核包并补完包里「最担心的问题」和 3–5 个审核问题。

到此停止。不写生产代码，不创建 probe 规格，不冻结候选路线，不确认路由。
```

### 阶段 B：写 probe 规格

```text
只写 probe 规格，不实现也不运行：

1. 为 <指定路线> 写 probe 规格，用 <项目根>/templates/spec_probe.md；
2. 找出这条路线成立所依赖的、最可能不成立的那一条假设，用它当证伪目标；
3. 判据必须在写规格时定死成数值，不能是「效果好」「收敛正常」；
4. 预算写死：≤50 行核心代码、≤1 分钟、玩具规模；
5. 运行 make spec-check 确认通过。

到此停止。不写实现代码，不运行 probe——那是编程手的事。

记下你写这份规格花了多少分钟，报告时告诉我。
```

### 阶段 C：写 full 规格

```text
只对 probe 已经 PASS 且实验板有对应记录的路线写 full 规格：

1. 用 <项目根>/templates/spec.md，八段齐全；
2. front matter 的 probe_spec_id / probe_exp_id / probe_result 必须指向真实存在
   且已跑过的 probe；
3. 写完后逐段自检：只读这一段，看不到本会话的人能不能唯一确定实现？不能的
   写进第 8 段未决问题——第 8 段为空是可疑信号；
4. 运行 make spec-check 确认通过。

到此停止。不实现。

记下你写这份规格花了多少分钟，报告时告诉我。
```

## 常见错误

- **一次放开全部三段**：它会一路做到 probe，中间的门控全部跳过。
- **让它自己跑 probe**：那是编程手的事。建模手跑了，「忠实实现」就没有被测到。
- **接受空的第 8 段**：真实建模很少一次定完所有细节，空的通常意味着它把没想清楚
  的地方默认交给下游猜了。
