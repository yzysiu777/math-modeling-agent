# 启动模板：对抗审核 C1 / C2 / C3

## 什么时候用

| 节点 | 时机 | **不要**什么时候 |
|---|---|---|
| C1 题意 | 题意重构完、路由确认前 | 已经开始写代码之后——那时改题意成本太高 |
| C2 架构 | 候选路线成形、准备冻结 Champion 前 | 只有一条路线时，没得比 |
| C3 结果 | 主要结果稳定、准备写摘要结论前 | 结果还在变时，审完就失效 |

**每个节点一个全新会话**，不要复用 —— 复用了它带着上个节点的印象，那也是污染。

## 两种用法

**A. 输出到对话（推荐用于 C1）** —— 它把报告打印在对话里，你当场读、当场给
修改意见、它改完再出一版。定稿后你或调度者复制落盘。迭代快，适合题意这种
需要来回讨论的节点。

**B. 交给外部模型** —— 复制审核包给 Gemini / Grok / 隔离的新任务。适合你想要
真正不同厂商视角的时候。用法 B 时把「文件路径」那段换成粘贴包正文。

## 填空清单

| 槽 | 填什么 |
|---|---|
| `<项目根>` | 工作台仓库绝对路径 |
| `<节点>` | `C1` / `C2` / `C3` |
| `<可读文件清单>` | **按名单列绝对路径**，见下面各节点的建议清单 |
| `<包路径>` | 审核包绝对路径（用法 B 时改为粘贴正文） |

## 提示词正文

```text
你是 Independent Reviewer，本次只做 <节点> 一个节点，不产出主解，不做最终裁决。

先完整读取 <项目根>/REVIEWER.md 和 <项目根>/prompts/reviewer/ 下对应节点的提示词。

可读材料——只有这些，不要读清单外的任何案例文件（尤其不要读 models/、specs/、
comparison.md，那是主解的结论，读了会锚定）：

<可读文件清单>
<包路径>

关于你自己的通用知识：你的通用建模知识、流程技能、与本案例无关的记忆**可以用，
不构成污染，不要因此判自己的报告无效**。判据是「它是否携带本案例的解释」，
不是「它是否来自包外」——人类专家也带着通用知识来审。在「已检查范围」里说明
你用了什么即可。

不要向我索取主解的会话记录或推理过程。材料不足以判断时，正确的结论是 BLOCKED
并写明缺什么，不是要更多上下文。

报告直接打印在对话里，不要写任何文件。用 REVIEWER.md 里的固定输出格式，
每条 finding 必须带证据（指向材料里的具体位置）、影响和最小验证测试。

「方案看起来合理」不是审核结论。「未检查范围」那一栏空着的报告是无效报告。

输出后停下等我的意见，不要自行修改任何文件。
```

## 各节点的建议可读清单

### C1 题意

```text
<案例目录>/input/题面_原文.md        ← 必须是原题全文转写
<案例目录>/input/数据字典.md
<案例目录>/case_brief.md
```

**并在提示词里加这段顺序约束**（C1 专用，比会话隔离更能防锚定）：

```text
工作顺序不要颠倒：先只读题面原文，独立写出你对研究对象、输入、输出、目标、
硬约束、单位、时间边界的理解，以及题面明确规定了什么、明确没规定什么。
写完之后再读 case_brief.md，逐条对照。

反过来做，你会照着 brief 的框架去读原题然后确认它——这是 C1 最常见的失效方式。

如果给你的「题面」是主解写的摘录而不是原题全文，直接报 BLOCKED：
你审的是转述，核不出转述有没有走样。
```

### C2 架构

```text
<包路径>          ← 包里已含 Champion/Challenger 规格的关键段与 probe 结论
```

C2 用包就够，不要另给案例文件 —— 包已经把该给的段落摘出来了，多给等于让它
看到主解的取舍理由。

### C3 结果

```text
<包路径>          ← 包里已含强主张原文、数据片段、复算结论、图表条目
```

同上。C3 额外要求：**局部复算**包里给的数字，不要只看它们自洽。

## 常见错误

- **写「不要读取任何文件」这类绝对禁令**：实测中审核者据此把自己的通用技能也
  算作违规，自判报告无效，整次审核作废。要写**按名单允许**，不要写全面禁止。
- **拿主解写的摘录当题面**：C1 要核的正是转述有没有走样。实测中 1347 字符的
  「本次范围摘录」被当成题面，而原题是 7805 字符。
- **给它案例目录让它自己找**：它会顺着目录翻进 models/ 和 specs/。给具体文件路径。
- **包头是 packet_complete: false 还硬送审**：缺证据的审核只能得出 BLOCKED，
  先补齐再送。
