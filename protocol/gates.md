# 阶段门禁与裁决规则

## 状态

- `PASS`：当前门禁通过，没有已知阻断项；
- `PASS_WITH_LIMITATIONS`：可以继续，但限制必须进入论文和交接；
- `BLOCKED`：存在 P0/P1 或关键证据缺失，停止推进；
- `REJECTED`：当前路线被题面、数据、推导、反例或复现否定；
- `PENDING`：检查已开始但证据未完成。

## 门禁表

| Gate | 名称 | 必须回答的问题 | 最低证据 |
|---|---|---|---|
| G0 | 目标批准 | 做什么、不能做什么、何时交付？ | 人工确认 + `project_manifest` |
| G1 | 路由与题意 | 题型、对象、输入、输出和约束是什么？ | `problem_contract` + `routing_record` |
| G2 | 输入冻结 | 资料是否可追溯且未被修改？ | 来源清单 + SHA-256 |
| G3 | 数据契约 | 字段、单位、标签、切分和质量是否明确？ | 数据字典 + 质量报告 |
| G4 | 假设与指标 | 符号、单位、目标和评价口径是否固定？ | 假设表 + 接口契约 |
| G5 | Baseline | 是否有简单、可解释、可运行基线？ | 运行记录 + 小案例 |
| G6 | 模型正确性 | 公式、目标、约束和代码是否一致？ | 推导 + 测试 + 约束检查 |
| G7 | 结果可信度 | 对照、稳定性、敏感性和边界是否充分？ | 实验卡 + 结果复算 |
| G8 | 对抗审核 | 独立审核是否发现 P0/P1？ | Claude/人工 `review_record` |
| G9 | 独立复现 | 另一角色能否按记录复跑？ | 复现记录 + 输出哈希 |
| G10 | 论文证据 | 结论、数字、图表和引用是否绑定？ | claim register + 论文审计 |
| G11 | 官方格式 | 当届规则、匿名和 AI 记录是否满足？ | 当前官方文件 + 预检 |
| G12 | 最终 PDF | PDF 内容、版式、元数据和哈希是否合格？ | 文本/渲染 QA + PDF hash |
| G13 | 人工冻结 | 谁确认模型、限制和最终提交？ | `human_signoff` |

## 声明升级

```text
draft
  -> supported
  -> supported_with_limits
```

以下任一改变必须降级并重新审查：输入或字段定义、标签或切分、目标/约束、代码/依赖/求解器、随机种子、关键参数、实验结果或论文强表述。

## 严重度

- `P0`：题意/数据/代码/结果根本错误、安全或权限违规；
- `P1`：会改变主要结论，例如数据泄漏、核心约束缺失、不可复现；
- `P2`：影响可信度、边界或推广范围，但可局部修复；
- `P3`：表达、排版或非关键改进。

## 通过规则

1. G2/G3 不通过，不能比较模型或训练复杂模型。
2. G5 不通过，不能声称复杂方法带来提升。
3. G6 不通过，不能报告满足约束的最优或可靠结果。
4. G7 不通过，不能把单次输出写成稳定结论。
5. G8 存在未解决 P0/P1，必须阻断定稿。
6. G9 未完成，只能标记“未独立复现”。
7. G10/G11/G12 任一不通过，不能提交论文。
8. G13 必须由人工完成，模型不得自行签署。

## 审核裁决

- 审核作者不能关闭自己提出的 P0/P1；
- Claude/Codex 一致只能作为待验证线索；
- 冲突由确定性测试、独立复现或人工裁决，并保留所有历史审核；
- 发现修订必须带 `approved_findings`、文件白名单、前后哈希和复验记录。
