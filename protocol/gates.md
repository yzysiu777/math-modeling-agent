# 阶段门禁与裁决规则

## 状态

- `PASS`：满足当前门禁，无已知阻断项。
- `PASS_WITH_LIMITATIONS`：可以继续，但必须在论文中披露限制。
- `BLOCKED`：存在 P0/P1 问题，不得推进。
- `REJECTED`：当前路线被数据、推导、反例或复现否定。
- `PENDING`：证据尚未完成。

## 门禁表

| Gate | 名称 | 必须回答的问题 | 最低证据 |
|---|---|---|---|
| G0 | 目标批准 | 做什么、不能做什么、何时交付？ | 用户确认 + `case_manifest.yaml` |
| G1 | 数据契约 | 字段、单位、标签、切分和来源是否明确？ | 字典、哈希、质量检查 |
| G2 | Baseline | 是否有简单可解释的可运行基线？ | 运行日志 + 小例子/指标 |
| G3 | 模型正确性 | 公式、目标、约束和代码是否一致？ | 推导、单元测试、边界测试 |
| G4 | 结果可信度 | 指标、敏感性、稳定性和对照是否足够？ | 实验卡、对照、图表 |
| G5 | 对抗审查 | 独立审查是否发现 P0/P1？ | Claude/人工审查报告 |
| G6 | 独立复现 | 另一环境/另一角色能否复跑关键结果？ | 复现记录、输出哈希 |
| G7 | 论文定稿 | 结论、限制、引用和图表是否对应证据？ | final gatekeeper + 人工签署 |

## 声明升级

```text
draft
  → supported（直接证据 + 通过相关测试）
  → supported_with_limits（有边界但仍可使用）
```

遇到以下情况必须降级：

- 关键输入字段解释改变；
- 训练/测试边界改变；
- 目标函数或约束改变；
- 代码、依赖、随机种子或求解器版本改变；
- 审查者提出未解决的反例；
- 复现结果与原结果不一致。

## 严重度

- `P0`：题意、数据、代码或结果根本错误；安全或权限违规。
- `P1`：会改变主要结论，例如数据泄漏、核心约束缺失、结果不可复现。
- `P2`：影响可信度或推广范围，但可局部修复。
- `P3`：表达、排版、可读性或非关键优化问题。

## 通过规则

1. G1 不通过，不能比较模型。
2. G2 不通过，不能声称复杂模型带来提升。
3. G3 不通过，不能报告“满足约束的最优解”。
4. G4 不通过，不能把单次运行结果写成稳定结论。
5. G5 存在未解决 P0/P1，必须阻断。
6. G6 未完成，只能写“候选结果/未独立复现”。
7. G7 需要人工确认；模型不得自己签署最终论文。
