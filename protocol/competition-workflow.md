# 华为杯竞赛核心工作流

本工作流只有一条主线，适用于运筹优化、数据分析和混合建模。它服务于四天赛程：
前期扩大方法空间，中期用实验收敛，后期把稳定结果同步写成论文。

```text
题意重构
  -> 多路线头脑风暴
  -> 候选模型池
  -> 快速 baseline
  -> 小实验赛马
  -> Champion / Challenger
  -> Claude C1/C2/C3 关键挑战
  -> 深化模型与稳健性实验
  -> 论文同步写作
  -> 最终数值与格式检查
```

## 1. 题意重构

从题面直接提取子问题、输入、输出、目标、硬约束、字段、单位、时间边界、评价
指标和交付物。只把会改变路线的歧义交给队员确认；其他未知先写入“尚缺信息”，
允许可逆探索。路由只有 `optimization`、`data_analysis`、`hybrid` 和
`insufficient_information`。

## 2. 候选模型池

每个关键子问题默认提出至少三条方法论不同的路线。路线卡必须有核心思想、数学
表达、关键假设、数据需求、实现/运行成本、预期优势、风险和最便宜的证伪实验。
可先读取 `.agents/skills/industrial-mathematical-modeling/references/` 下对应的实战方法卡。
`scripts/model_pool.py` 检查空字段、明显重复的方法族和状态；真正的方法论差异仍由
Codex、Claude C2 与队员判断。

运筹题按适用性覆盖精确规划、网络/动态规划、分解或松弛、启发式/元启发式、鲁棒
或随机优化、仿真优化。数据题按适用性覆盖描述统计、线性/广义线性、树模型、时序、
聚类和神经网络。混合题写清分析输出到决策模型的字段、单位、误差和场景规则。

## 3. Baseline 与实验赛马

先跑小规模、手算、穷举、合成数据或短迭代。优化题先有规则、线性模型、网络算法
或小规模规划；数据题先有统计量、朴素预测或线性模型；混合题先连接简单分析器
和决策器。实验使用统一切分、约束口径、实例范围和指标，优先选择能区分路线且
成本低的实验。

实验板的每一行至少说明实验 ID、候选路线、问题、最小配置、数据/实例范围、指标、
成本、状态、结果摘要、是否继续投入和下一项信息价值最高的实验。保留 Champion
与至少一个方法论不同的 Challenger；淘汰路线只保留简短理由和证据。

普通数据、实验输出和中间文件记录来源、日期、大小和可复现命令。官方文件、最终提交
PDF 或团队指定的里程碑版本可以额外记录 SHA-256，方便确认文件身份。

## 4. 三个关键挑战

- C1：题意、目标、约束、单位和遗漏；必要时盲审；
- C2：模型架构、算法、公式—代码一致性、替代方法族和反例；
- C3：主要结果、对照公平性、泄漏、稳定性、数字来源和论文强结论。

每次给 Claude 的包只保留完成该节点所需内容。Claude 不重跑整题，只输出最高风险
问题、方法论不同的挑战视角、最便宜的区分实验、路线建议、人工决定和未检查范围。
队员把采纳/拒绝及原因写入 `decisions.md`。

## 5. 深化与论文

路线确定后再扩大规模、做敏感性/稳健性/消融和误差分析。实验一稳定，就同步维护
符号表、公式、算法、图表需求、结果段和引用。不要等所有代码完成才写论文。

## 6. 最低质量检查

- 题面和原始附件没有被覆盖，字段和单位明确；
- 数据切分、标签生成和泄漏风险已经检查；
- 优化解的约束与目标已经独立复算；
- 关键统计指标、随机种子、参数、代码入口和输出可复现；
- 论文公式、代码、图表、引用和结论一致；
- LaTeX 编译、引用、匿名信息、PDF 文本和版式通过检查；
- 当届官方模板、AI 规定和提交手册已在比赛日重新核对。

## 7. 四天节奏建议

| 时段 | 重点产出 |
|---|---|
| 第 1 天 | 题意重构、三条以上路线、baseline、最小实验 |
| 第 2 天 | 实验赛马、Champion/Challenger、C2、正式模型骨架 |
| 第 3 天 | 稳健性/敏感性、C3、图表、结果与讨论段落 |
| 第 4 天 | 摘要结论统一核数、格式/匿名/引用检查、PDF 和人工提交确认 |
