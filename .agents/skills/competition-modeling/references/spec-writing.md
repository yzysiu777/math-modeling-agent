# 写规格：让陌生人能实现

规格的读者是**看不到你会话的编程手**。他不知道你想了什么，只知道你写了什么。

模板：`templates/spec.md`。只有进入正式实现的路线才写五段 Full SPEC；
Probe 直接写 `q<k>/board.md` 的一行，不建独立规格。
契约规则：`prompts/contracts/spec.md`。

## 唯一的自检方法

写完每一段，问一句：**只读这段，能不能唯一确定实现？**

不能 → 要么补写清楚，要么写进第 8 段「未决问题」。**不要指望下游猜对。**

## 逐段要点

### 1. 目标与判据

判据必须**可判定**：数值、布尔或明确的比较关系。

| 不可判定（重写） | 可判定 |
|---|---|
| 结果合理 | 12 个实例全部可行，且目标值与枚举真值相对误差 ≤ 1e-6 |
| 效果比 baseline 好 | 测试集 RMSE 比 M-01 低 ≥ 5%，且 5 折结果标准差 ≤ 0.02 |
| 收敛正常 | 500 次迭代内 gap ≤ 1%，或提前满足终止条件 |
| 速度可接受 | 单实例求解 ≤ 300 s |

写完判据问自己：**编程手跑完之后，能不能不问我就判断出通过还是失败？** 不能就重写。

### 2. 数学表述

- 每个符号有含义、变量域、单位；
- 约束逐条编号，方便回问时引用「C3 和 C7 单位不一致」；
- 目标函数写明 min 还是 max；
- 符号与 `q<k>/brief.md`、论文符号表**一致** —— 同一个量不要在两处用不同符号，
  否则论文阶段要花大力气对齐。

单位自检：把每条约束的左右两边单位写出来，对不上就是错的。这一步能抓出大量隐藏错误。

### 3. 数据契约

**去 `input/` 实际核对字段名，不要凭题面描述写。** 这是规格最高频的失效点 ——
题面说「时间戳」，实际列名可能是 `t_stamp`、`Time` 或 `采集时间`。

缺失值、异常值、切分规则**写死**：

| 不要写 | 要写 |
|---|---|
| 缺失值按情况处理 | `age` 缺失填中位数；`label` 缺失整行删除；其余列缺失保留为 NaN 传给模型 |
| 合理划分训练测试 | 按 `date` 切，2023-01-01 前训练，之后测试；不打乱，不分层 |
| 去掉异常值 | `speed` > 200 或 < 0 的行删除并记录数量；其余列不做异常处理 |

### 4. 算法

伪代码 3–8 行足够，不要写成代码。要有的是：求解器与关键参数、随机种子、终止条件、
规模与时间预算。

**时间预算必须写。** 没有预算，编程手不知道跑到什么时候算失败，会一直等。

### 5. 输出契约

列名写全，路径写死。编程手照着能直接建表，写作手照着能直接取数。

图表产物表里，每个 FIG-ID 要写清 x 轴、y 轴（含单位）和必须标注的内容。
「画个收敛曲线」不是输出契约。

### 6. 复算要求

**full 规格这段为空，等于放弃了正确性保障。**

要写清复算什么、用哪个函数、判定阈值多少。关键是要求**独立重算** ——
用主求解器自己算出的目标值去验证它自己，什么也验证不了。

主实现是 MATLAB 时，复算仍要有 Python 版本：阶段检查和 CI 只跑 Python。

### 7. 明确不做

列出范围外的事。这段防的是编程手「顺手」多做 —— 顺手加个约束、顺手调个参、
顺手多画两张图。多做的部分没有规格背书，论文里没法引用，还消耗时间。

### 8. 未决问题

**这段为空是可疑信号。**

真实建模过程很少一次定完所有细节。第 8 段空着，通常意味着你把没想清楚的地方
默认交给下游猜了 —— 而下游会猜，还会猜得很自信。

写进去的每一条要有：未决内容、影响范围、你计划何时定。

## 规格改动

改了就更新文件。如果改动影响目标、硬约束或结论强度，同时在 `decisions.md` 记一条。

**同一份规格反复被回问同类问题** → 说明那一段写得不够具体，重写整段，不要逐条答复。

## 检查

```bash
make spec-check CASE=cases/<case_id>
```

`scripts/check_spec.py` 只查字段齐全、状态合法、判据非占位、full 规格的输出契约与
复算要求非空。**它查不出建模是否正确，也查不出判据是否合理** —— 那是 C2 和队员的事。
