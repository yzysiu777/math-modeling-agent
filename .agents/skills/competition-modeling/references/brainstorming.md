# 头脑风暴：先发散，再收敛

竞赛前期最贵的错误不是选错方法，是**过早收敛** —— 只想了三个方法就开始写代码，
而那三个恰好是你最熟悉的三个。那不是搜索，是回忆。

## 第一轮：发散（禁止评价）

每个关键子问题列 **≥6 条**想法。这一轮只记录，不评价、不筛选、不问「这个能不能做」。

### 强制跨方法族取样

不要在同一个方法族里凑数。按路由从下面各取几条：

**运筹方向**

| 方法族 | 触发信号 |
|---|---|
| 精确规划（LP/MIP/CP） | 关系大体线性、规模可控、要最优性证明 |
| 网络流 / 动态规划 | 能画成图、有阶段结构、有无后效性 |
| 分解与松弛（Benders/拉格朗日/列生成） | 结构可分、耦合约束少数几条 |
| 构造式启发式 | 规模大、要快速可行解、要 baseline |
| 元启发式（GA/SA/TS/ALNS） | 解空间复杂、可接受近似 |
| 鲁棒 / 随机优化 | 参数不确定且题面强调这一点 |
| 仿真优化 | 系统动态复杂、解析表达困难 |

**数据方向**

| 方法族 | 触发信号 |
|---|---|
| 描述统计与假设检验 | 要回答「有没有差异」「是否显著」 |
| 线性 / 广义线性 | 要可解释系数、样本不大 |
| 树模型（RF/GBDT） | 特征多、非线性、交互作用 |
| 时序模型 | 有时间顺序、要外推 |
| 聚类与降维 | 要分群、要压缩特征 |
| 神经网络 | 数据量大、结构化信号强（图像/序列） |
| 贝叶斯 / 半参数 | 要不确定性量化、先验信息可用 |

**混合方向**

| 方法族 | 触发信号 |
|---|---|
| 两阶段（预测后优化） | 上下游可清晰切开 |
| 端到端 | 预测误差对决策影响大 |
| 场景生成 + 随机规划 | 不确定性可离散化 |
| 在线滚动 | 信息逐步揭示 |

### 刻意加两条极端路线

- **一条极简到不像建模的**：规则、查表、贪心、常数预测。它给出下界，也常常出人意料
  地难被超过 —— 如果复杂模型只比它好 2%，那是重要发现。
- **一条明显超预算的**：完整精确模型、全枚举、最复杂的方法。它给出上界，让你知道
  中间路线离天花板有多远。

这两条通常不会赢，但它们框定了区间，让中间路线的价值第一次变得可测量。

## 第二轮：收敛

筛到 **≥3 条方法论真正不同**的路线。

### 「真正不同」的判据

底层**数学结构**不同，不是同一模型换参数、换求解器或换表述。

| 是同一条路线 | 是不同路线 |
|---|---|
| MIP 的 arc-flow / path-flow / time-indexed | MIP vs 动态规划 vs 元启发式 |
| 随机森林 500 棵 vs 1000 棵 | 随机森林 vs 线性模型 vs 时序模型 |
| 换求解器（CBC → Gurobi） | 精确求解 vs 拉格朗日松弛 |
| 换核函数 | SVM vs 树模型 |

自检问题：**如果路线 A 因为某个假设不成立而失败，路线 B 会因为同一个假设失败吗？**
会 → 它们不是独立的路线，只是同一条路线的两种写法。

`scripts/model_pool.py` 查不出这种重复（它只比对方法族字符串），得你自己判，
C2 独立审核会再查一遍。

### 淘汰要标层

排除理由里出现「必须离散化」「状态空间爆炸」「计算量过大」「只能近似」「需要自定网格」
这类说法时，**停一下问三句**：

1. 排掉的是方法族，还是这一种实现？换一种表示（存函数而不是存网格、存参数而不是枚举、
   存断点而不是存格点）之后，障碍还在吗？
2. 理由里提到的结构性质（线性、凸、单调、可分、低维状态、解析可积）是**障碍**还是
   **钥匙**？很多时候正是它让这个方法族从近似变成精确；
3. 这个方法族有没有一种实现，精度**不依赖人为划定的粒度**（网格、分箱、时间窗、阈值、
   采样数）？有就先写进路线表，再谈成本。

三句都答完仍然排除的，把答案写进发散表的 `处置` 列。答不出来的不叫排除，叫没试。

### 淘汰要留痕

被砍掉的想法在 `q<k>/brief.md` 留一行：想法、砍掉的原因、是否有可复用部分。
比赛第三天经常需要回头捡起第一天砍掉的东西 —— 前提是当时写下了为什么砍。

## 常见失败模式

- **伪发散**：六条想法里五条是同一方法族的变体。检查方法族标签，重复的重新取样。
- **发散时就评价**：一边写一边说「这个太慢了」，结果只剩三条常规解法。评价放到第二轮。
- **收敛后不记录被砍的**：后面无法回溯，也无法向 C2 解释为什么没考虑某个明显方法。
- **把「我不会实现」当成淘汰理由**：实现难度是评估维度之一，不是发散阶段的过滤器。
  真正贵的是想不到，不是写不出。
